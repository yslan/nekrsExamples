=== this method vs the two reference approaches ===

  R1: treat the GLL nodal values as an N x N bilinear grid, marching
      squares with linear edge interpolation.
  R2: interpolate the field to a uniform MxM grid (M ~ 1.5N), then the
      same marching squares.
  Both use the SAME topology logic as ours; only the vertex locations
  differ -- linear interpolation versus exact rootfinding.

  READ THIS TABLE IN TWO HALVES.
  'circle' and 'ellipse' are POLYNOMIAL in (r,s): the GLL interpolant is
  exact, so the only error left is the contouring itself.  There our method
  is at machine precision and the reference methods are 1e13-1e15 times
  worse -- they are limited by LINEAR interpolation along a cell edge, which
  resampling shrinks but never removes.

  'twoblobs' and 'wavycircle' are NOT polynomials: the degree-N interpolant
  cannot represent them, and that interpolation error swamps everything.
  All three methods then agree to within a small factor -- exact rootfinding
  buys nothing once the polynomial itself is the wrong curve.  This is the
  conditioning floor of section 2, seen in 2D: a rootfinder cannot beat the
  interpolant it is given.

=== high-order refinement of the extracted contour (N=8) ===

  The marching step emits straight segments between EXACT vertices.  The
  chord between them is the only error left.  Two ways to remove it, both
  using information the polynomial already has -- neither is a fit:
    hermite : exact unit tangents (grad f is perpendicular to the contour)
              -> cubic Hermite, C^1 at every vertex
    project : subdivide, then Newton each new point onto the contour,
              x <- x - f grad f/|grad f|^2 .  The new nodes are exact roots.

  Error is the max distance of the WHOLE curve (sampled at 65 points per
  segment, between the nodes as well as at them) from the true level set.

  Reading the table:
  * straight is flat in k -- subdividing a chord does not move it.
  * hermite gains an order of magnitude immediately, then PLATEAUS: a cubic
    cannot represent the contour exactly, so refining it converges to the
    cubic's own error (circle: 8.5e-04 at k=31, already 9.4e-04 at k=15).
  * project keeps converging, because every added node is an exact root;
    only the chords between them remain, and those shrink with k.
  * on 'twoblobs' and 'wavycircle' all three tie: the interpolant itself
    is the wrong curve (the conditioning floor), and no refinement of a
    wrong curve helps.

  Cost per added point: hermite ~2 gradient evals (once per vertex,
  amortised); project adds 3 Newton steps x 3 evaluations.

  'at nodes'  : |f-c| at the triangle corners -- machine precision, they
                are exact fibre roots.
  'flat tri'  : |f-c| sampled INSIDE the flat triangles -- the chord error,
                the only thing left after exact vertices.
  'projected' : after 2 subdivisions with every new node projected onto the
                surface (x <- x - f grad f/|grad f|^2).  ~4x smaller per
                subdivision, and the surface renders smooth.

  NOTE on 'tangency': the field (r^2+s^2+t^2-0.5)^2 is a perfect square and
  is non-negative everywhere, so it TOUCHES the level without crossing.  No
  marching-cubes corner sign changes and 0 triangles are emitted -- which is
  correct: a measure-zero tangency is not a surface MC can represent.  The
  fibre solver nevertheless finds the tangency locus (60 roots), with p'~0
  flagging every one of them.  This is the section-2 tangency case seen in 3D:
  detect and report, do not pretend to triangulate.
    circle      sphere r^2+s^2+t^2 = 0.6^2  [2D 'circle' + t^2]
    twoblobs    two disjoint spheres  [2D 'twoblobs' + t-offset]
    saddle      r*s + 0.25 t = 0.15: the ambiguous case  [2D 'saddle' + 0.25t]
    tangency    (r^2+s^2+t^2-0.5)^2 = 0: double root  [2D 'tangency' + t^2]
    wave        sin(2.6 pi r) + cos(2.2 pi s) + 0.6 sin(1.8 pi t) = 0.3  [2D 'wave' + t]
    band        thin sheet: forces line insertion  [2D 'band' + t]
    corner      r+s+t = 1.15: plane clipping the corner  [2D 'corner' + t]
    ellipse     ellipsoid r^2 + 2.6(s-0.12)^2 + 1.6 t^2  [2D 'ellipse' + 1.6t^2]
    wavycircle  wavy sphere  [2D 'wavycircle' + t^2]
    torus       genus-1 tube (NO 2D analogue: topology that needs 3D)
